2. 残りをそのまま本文に貼る。`##` の見出しはそのまま見出しとして認識される
3. 画像は自動では入らないので、`![…](images/…)` の位置で手動でアップロードする。
   ファイル名の番号が本文に出てくる順番です

### 画像について、書き手が知っておくとよいこと

- **服の写真はイラストです。** 実物の服の写真を撮れないため、平面のイラストを15点つくって
  アプリの「写真を選択」から登録しました。本文の 📱 の節に
  「この記事に載せている画面の写真は、説明のためにイラストを登録したものです」と一文入れてあります。
  ご自分のクローゼットで撮り直せるなら、そのほうが記事の説得力は上がります。その場合はこの一文を消してください
- **AI が返した結果の画面は撮っていません。** Gemini の鍵を持っていないためで、
  出せない答えを載せるわけにいかないので、入口の画面までにとどめています。
  鍵をお持ちなら、解析結果と提案結果を撮り足すと記事が強くなります。
  撮り足す場所は 🤖 の節、`19-ai-add.png` と `20-ai-stylist.png` の直後です
- 設定画面に「アプリとして使う」の案内が出ていないのは、撮影に使ったブラウザが
  ホーム画面への追加の合図を出さないためです。実機では出ます

## 撮り直すときの手順

撮影に使った一式は、納品時に消してあります。もう一度撮るときは次の形で組み直せます。

```bash
npm i --no-save playwright
npm run build
node <skill>/scripts/serve.mjs dist 4180 /DigitalCloset/     # 別ターミナル
node <skill>/scripts/capture.mjs shots.mjs --base http://127.0.0.1:4180/DigitalCloset/ --out shots
```

撮るときに踏んだところを残しておきます。

- 見本のデータは、書き出しファイルの読みこみではなく、**アプリの追加画面から1着ずつ登録**した。
  実際に通る道を通したかったため。着用記録もカレンダーから1件ずつ押して入れた
- 写真の取りこみが、まれに1回目で反映されない。入ったかどうかを
  「写真を追加」ボタンが出たかで確かめ、出ていなければ入れ直す。
  確かめずに進めると、以降ずっと空の追加画面を撮り続けることになる
- 下のタブは `aria-label` が「カレンダータブ」だが、文字は「カレンダー」。
  文字で押す仕組みでは「カレンダー」で当てる
- カレンダーの日付とコーデの選択は `div` に押す仕掛けが付いていて、
  ボタンを探す仕組みでは拾えない。素の Playwright に降りて押した
- ★は `svg` なので `click()` が無い。イベントを直に投げる
- 画面を出したあとにビューポートを伸ばすと、下のタブの描き残りが上のほうに写りこむことがある。
  伸ばすなら画面を出す前に伸ばすか、伸ばさずに撮る
